# 验收与公开交付

## 自动检查到底做了什么

`check` 在 Chromium 的 print 模式以真实物理画布测量：整张纸内的元素边界、主要文字/卡片容器的明显溢出、图片加载与栅格清晰度提示、成品占位符。

`export` 再核对一页与尺寸（误差不超过 1mm），从生成 PDF 的二维码区域解码，并与该二维码链接的 href 比对。无 href 的二维码只能证明可解码，仍需手机确认真实目标。72 DPI 仅用于审阅，150 DPI 阶段图，300 DPI 最终图。

**自动检查没有验证**：科学数据/结论、作者身份、会议规则、字体许可证、视觉美感、所有内部重叠、所有元数据/隐私。它不是内容审稿；报告明确标记 `content_audit: NOT_RUN`。不能把通过布局检查说成“全都没问题”。

## 人工终检清单

- [ ] 当前会议的尺寸、方向、输出要求已查当年官方来源。
- [ ] 标题、作者、顺序、机构、通讯作者标记、paper ID 正确。
- [ ] 数字逐条对应 EVIDENCE；比较指标、单位、任务、条件一致。
- [ ] 摘要结论与实际证据匹配，无无依据的宣传词。
- [ ] PDF 放大看四边、徽章外轮廓、图轴文字和二维码；没有裁切或假透明导致消失。
- [ ] 远看主次清楚，近看图标签可读。编号与任务名比说明字更突出。
- [ ] 各区无孤立换行、巨大空槽；留白有理由，不能靠填废话补齐。
- [ ] 从最终 PDF 解码成功，再手机扫码验证目标；quiet zone 不被裁掉。
- [ ] 印刷按 actual size / 100%，不让“适应纸张”改变物理尺寸。
- [ ] 内容与资产最后修改后重新 export；旧检查不能覆盖新源码。

## 打包隐私

先逐项确认公开范围。邮箱、个人主页、微信二维码是否允许公开由本人决定；一次允许不自动传递到下一个项目。论文作者与机构是正式署名，不能为了“匿名化”误删必要署名，也不能随意加未经确认的简介。

工具只收 `poster.html` 引用的本地图片、最终 PDF/300dpi PNG/单文件 HTML、必要脚本与运行说明。拒收过程笔记、未引用图片、隐藏文件、符号链接和非预期附件。打包前还会确认源码/引用资产哈希未变化，检查部分常见本机路径、凭证模式与图片元数据。

元数据检测不是完整 DLP。SVG 里的注释、数据 URI 的内部内容、截图本身、PDF properties 或附件都要人工看。不要在项目 assets 混入身份证、签名、成绩单和邮件证明；未引用也不该依赖脚本帮你兜底。

需要清理元数据时另做交付副本，不修改原始存档。清理后验证视觉/像素一致，再重新导出。不上传到在线“去背景/压缩/检测”服务。

最后的 zip 只是交付包。GitHub push、邮件发送、系统提交需要用户另行明确授权；不要顺手推送整个个人资料目录。
