# 创作流程：先取舍，再排版，再微调

## 1. 输入与证据

先拿论文 PDF，最好同时有 LaTeX 和原始图。读取摘要、动机、方法、实验表、作者信息，不靠聊天记忆复述。记录会议当年的官方海报规则与查验日期：画布、方向、字体下限、允许的标识和输出格式。模板的 A0 只用于开始，不是会议通用规定。

`BRIEF.md` 写目标和边界；`EVIDENCE.csv` 把每个拟展示数字对应到页码、表格、行列、指标、任务和实验条件。方法比较与编码/表示比较分开；可比性先于倍率。作者序、机构、共同作者和通讯作者符号直接核对原文。个人简介与身份另由本人确认。

## 2. 决定读者的三种停留时长

- 3 秒：标题、问题或主图，让人知道研究什么。
- 30 秒：为什么现有做法不够，以及你改了什么。
- 3 分钟：机制、代表性证据，继续讨论或扫码。

先写“这张海报要让别人记住的一句话”，再给每个区域一个工作。海报不是缩小的论文：不必照搬 Abstract/Introduction/Related Work；完整超参、推导和大表可以留在论文和口头讲解中。

## 3. 用候选图选设计，然后锁定

从三个骨架选择最合适的两三个，放入真实标题、一句话问题和主图，先低分辨率预览。让用户对比结构，不只对比紫/蓝换色。确认一个方向后记在 `DECISIONS.md`：画布、配色、字体、块数、主要视觉、保留与删除内容。

不要每次修改都重新选模板。海报内容的重点也是设计锁的一部分：例如本次优先动机和 R1–R3 分析，并不意味着每篇论文都应有三个 R。

## 4. 填内容并做第一遍压缩

先整体替换 TODO，再处理字号和高度。每段承担一个信息任务；机制可写“输入 → 操作 → 输出”，不用三段实施细节。结果区用大任务名、大关键值、小比较条件，配一两句真正的结论。宁可一幅清晰的图加一句解释，也不要小图旁边堆满文字。

证据不能压缩丢失：删掉宣传腔，不删指标定义、比较对象或必要前提。别为了显得全面加入最夸张的异常案例。标题、二维码标签和机构名是功能标签，不必写成论文腔。

## 5. 小步迭代，预览为主

一次解决一到三个明确问题，例如“所有任务标签加大”“这段压缩两行”“标志作为一组左移”。只编辑相关组件，不顺便重写整张海报。改完刷新 localhost；有重排时跑 `check`，再看局部和全局。

关注修改是否真的成立：字号增大后有无换行？裁边是否伤到校徽轮廓？QR 里的微信图案是否让视觉重量更大？以预览判断光学平衡，不只看 CSS 框的尺寸。被用户否决的尝试记录下来，便于准确撤回。

**检查不等于归档**：局部修改需要重新验证受到影响的布局/资源，但不必生成永久 PDF/PNG。阶段审阅用 72/150 DPI；内容与结构锁定后才生成最终 300 DPI。不要用无数 `final_vN` 混淆当前版本。

## 6. 印刷、可读性与交付

真正的验收对象是 print 模式导出的 PDF，而非缩放网页。核对一页、尺寸、所有图、字体、四边、作者区和底栏；解码 PDF 上的二维码，手机也扫一次。最后给出 PDF、PNG、HTML/CSS、必要资产和导出代码。

保留本地证据和过程记录；公开包只收最后的结果与必要代码。发布 GitHub、发邮件、提交会议系统是另外的授权动作，本工具不会自动执行。
