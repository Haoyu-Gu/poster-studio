# BeatEdit 海报迭代记录

记录制作过程中有用的反馈和调整。

## 有效的决策

| 当时的反馈 | 可复用的做法 |
|---|---|
| “开 localhost，开始改文件” | 保持一个活的编辑预览，避免只看图库 PDF 或描述设计。 |
| “重心放动机和分析” | 先确定贡献叙事，再决定实验占多少面积。 |
| “极端案例不要，放编码对比” | 方法提升与表示性质是两条证据线；用可比的代表数据。 |
| “两行以内，不放大表” | 结论简短，关键数值大；海报天然不展示全部结果，不必自称 Selected。 |
| “标题在第一行，标志在下面” | 标題优先；作者、机构和多个标志放同一信息层。 |
| “南大校徽被啃了” | 每次裁边检查实际轮廓，不能依赖粗略遮罩或 object-fit:cover。 |
| “字体改完更丑，调回来” | 字体是整张纸的语气，换字体先局部试样；准确撤回，别继续叠修。 |
| “BEAT 特效去掉” | 方法名不需要每次出现都贴徽章、发光或强调。 |
| “二维码大一点，微信再小 3mm” | 统一外部槽和标签基线，允许图案有光学尺寸补偿。 |
| “白底扣掉” | 浅背景可尝试 multiply，保留二维码周围的 quiet zone。 |
| “可以夹带私货” | 作者介绍、个人主页、联系方式和前序工作是现场交流入口；留出位置但不抢主贡献。 |
| “最终结果和代码，不要中间过程” | 交付文件白名单；笔记、证明、签名、邮件与工作历史留在本地。 |

## 不该照抄的参数

二维码 72mm、微信 69mm、Rel 行 70% 底色是这张海报的具体选择。换纸张、素材密度、logo 形态后，按预览重新调整。

## 流程可以更快

过去每次微调都重新导出，产生了很多版本。改成“工作 HTML 一个、关键阶段快照少量、最终交付一套”。检查可以频繁，归档应有意义。

留白较多时，先看看图是否太小、内容是否重复、区域是否划得太高。优先调整图和区域大小，保留适当留白。

响应局部反馈时遵循：定位区域 → 修改一个共享参数/组件 → 预览 → 比较 → 记录确认。只要用户没有改变设计方向，就不重做整张海报。

## HTML 为什么适合这类协作

共享 token 方便统一调整字号和配色，Grid/Flex 便于保持组件对齐。SVG 和本地二维码适合高分辨率导出，源码也方便版本管理。定稿时检查浏览器打印布局、字体和物理尺寸。
